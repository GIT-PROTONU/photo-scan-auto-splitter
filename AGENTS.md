# AGENTS.md

Single-module app: `photosplit.py` contains everything — split algorithms, CLI, tkinter GUI, and the mask review dialog. Tracked files: `photosplit.py`, `README.md`, `LICENSE`, `PhotoSplit.spec`, plus `dev/baselines.json` (regression reference) and `dev/rect_tighten.patch` (archived dead-end, see Group-2 note).

## Commands

```bash
python3 -m py_compile photosplit.py                  # only static check available (no lint/test config, no CI)
python3 photosplit.py                                # GUI (no args = GUI)
python3 photosplit.py "Scan_20260918 (37).jpg" -o /tmp/out --tolerance 20   # CLI smoke test
python3 photosplit.py "Scan_20260918 (37).jpg" -o split --tolerance 20      # regenerate the gitignored split/ folder
python3 photosplit.py --regression ~/.local/share/Trash/files errors --compare dev/baselines.json   # gate-change regression check (exit 1 on any diff; --sig dev/baselines.json re-records after an accepted change)
```

`Scan_*.jpg` files in the repo root are gitignored personal scans — use them as smoke-test inputs, never commit them or anything in `split/`. `PhotoSplit.exe` and the portable zip are gitignored release artifacts.

## Architecture notes (non-obvious)

- Pipeline is intentionally split for the GUI review feature: `analyze_scan()` returns a state dict (`im`, `small`, `scale`, `bg`, `mask`, ...) and `extract_parts(st, mask)` does component splitting/watershed/extraction. The mask lives at the downscaled resolution (`maxdim=3200`); mask edits and their screen mapping are all at that scale. CLI path (`split_scan` → `process_file`) must stay behavior-identical.
- Photos butted edge-to-edge (no background gap, e.g. 2x2 grids or photobooth strips) are handled by `_seam_split()`: it finds near-axis-parallel gradient seam lines (slope ≤ ±0.06, column-coverage ≥ 0.68 of the span) inside a merged component and cuts along them recursively. Gates matter — they were tuned against real scans: dark text/design bands flanking a busy side are dropped (`_band_like`), pieces must be elongated (≥2.2) or ≥25% of page at ANY depth (a depth≥1 sub-piece of a 2x2 grid is usually a single photo — restricting this to depth 0 caused internal false cuts on real scans), sub-pieces ≥15%, and the cut line must be ≥10% in-mask (`_SEAM_SPAN_FRAC`). Accepted sides must also pass `_ext_corners()` (photosplit.py): Harris-family (Shi–Tomasi) corner detection on the downscaled piece silhouette, counting distinct corners on its convex hull — real photos form ~4 external corners, so pieces with >10 corners (ragged/irregular) or <4 corners without a rectangular silhouette (bbox fill ≥0.90 rescues rounded-corner photos; smooth blobs like ellipses have fill <0.80) reject the whole cut. Raising coverage gates back to 0.85 misses seams with bg gaps; loosening the slope range splits shirt collars/brick mortar lines. Gates re-tuned Sept 30 2026 against the `errors/` folder (12 real failure cases), all 9 root-scan baselines unchanged at tol 16 & 20: (1) seam evidence must terminate boundary-to-boundary — detected gradient columns must start/end within `_SEAM_EV_EDGE_FRAC` (0.12) of the blob span; this is the real safety gate. The in-mask line fraction was lowered 0.60 → 0.10 because 2x2-grid photos often touch only across part of the seam with a white bg gap along the rest (measured real touching-pair seams are 0.12–0.56 in-mask); boundary-to-boundary evidence keeps internal features out. If lo=35 finds nothing, a lo=25 retry runs — soft/low-contrast real seams (Scan_20260918 (13) right column) need it. (2) Post-cut sides go through `_crop_subs()` (label connected components, keep those ≥ max(400, _MIN_PIECE_FRAC*page)) instead of one bbox `_crop_sub` — a cut can leave photo + disconnected shards, and the raw bbox collapsed fill to 0.46 killing valid pieces; composite recursion allows nc ≤ 14 (11 was too tight for two stacked real photos). (3) `_quad_lock()` + the elong/area skip refuse seam search for clean single-photo quads (4–8 corners, fill ≥0.92, AR <2.2, <25% page) at every depth (loosening quad-lock AR to 3.0 would block stacked-wallet strips from splitting). (4) `_MIN_PIECE_FRAC = 0.01` (was 0.05): passport photos (~3.9% of page, Scan_20260925 (26)) and photobooth strip frames (~2.1%, Scan_20260918 (8)) are real photos and were being dropped by `_piece_ok`. (5) `_dedupe_parts` places each candidate at its true canvas origin `(qx+xs.min(), qy+ys.min())` — watershed/seam pieces of one component all shared the parent `(qx,qy)`, so the old code stacked them at one spot, measured >50% phantom overlap, and deleted all but one piece (the #1 cause of "missing" photos). (6) `analyze_scan` zero-pads the binary mask by 4px before MinFilter/MaxFilter and crops back: PIL replicates border pixels, so a 1–4px scanner-bezel line at the image edge was un-erasable and glued itself to photos (Scan_20260918 (33): fill 0.51 → rejected). (7) `_dt_seeds` suppresses seeds closer than 0.75×max(dt1,dt2) to each other (strongest first): elongated photos have flat distance-transform ridges that used to spawn duplicate seeds and split a single photo in half (Scan_20260925 (4) family portrait).
- Group-5 fix (Sept 30 2026): `_extract` deskew is clamped by `_MAX_DESKEW_DEG = 6.0`. A fitted quad angle beyond 6° is a silhouette-fit artifact of a ragged / white-merged mask, never a real flatbed rotation, so the piece is returned by `_axis_crop()` as a plain axis-aligned bbox crop (no rotation, no mask). The old code rotated these and clipped corners / left white triangles (errors 5, 6, 8, 9, 16, 20, 25-19). Do NOT lower the clamp to ~4°: a genuinely tilted single print reaches ~5° (baseline `Scan_20260918 (24)` fits at -5.2° and must stay deskewed); real artifacts are all ≥6.4°.
- Group-1 fix (Sept 30 2026): `_QUAD_LOCK_AREA` raised 0.25 → 0.33. A clean single-photo quad (4–8 corners, fill ≥0.92, AR <2.2) up to 33% of page is now locked against seam search. Fixes false internal-seam over-splits on `Scan_20260918 (12)` and `(9)` (5→4 pieces). Real 2-photo blobs are ≥~0.4 page so they are still searched; the 13 Trash baseline scans are unchanged at tol 16 & 20. Still NOT fixed by this lever: `Scan_20260918 (10)` and `Scan_20260925 (19)` — investigated Sept 30 2026, both are fundamental dead-ends for the seam/quad-lock subsystem. (a) Scan 10's whole page is one 0.94-page blob (white gutters don't separate the prints); the cathedral is over-split by a horizontal roofline seam that is only real in the neighbouring column, but the only axis-preference fix that keeps the cathedral whole (prefer the lo=35 vertical over the lo=25 horizontal) instead isolates the right column (boat+postcard, a clean 0.24-page quad) which quad-lock then refuses to split → a 2-photo merge, trading an over-split for a worse failure. boat+postcard (must split) and Scan-12-B / Scan-9 blobs (must NOT split) are all clean quads with lo=35 internal seams — no size/fill/corner/gmag threshold separates them. (b) Scan 25-19's over-split is NOT from `_seam_split` at all (every seam it finds is a real grid gutter, gmag 49–102); the extra pieces come from `_watershed`/`_dt_seeds` fragmenting the top-row component whose mask fill is only 0.25 (white-on-white holes create spurious distance-transform peaks). Retuning watershed risks the many grid baselines that rely on it to split a single merged blob into 4. Both need a content/semantic seam validator, not a gate tweak.
- Scan-6-at-tol-20 fix (Oct 2 2026): `_watershed` gained a COVERAGE gate — kept parts must tile ≥0.8 of the component mask area, else return `[]` and fall through to `_seam_split`. `_parts_from_assign`'s area/overlap filters can silently DELETE a whole photo (at tol 20 the bottom row of `Scan_20260918 (6)` is one blob; the tilted print spawned 2 seeds whose fragment bboxes overlap the neighbour's, so the neighbour was dropped and the print halved — coverage was 0.50). Seam machinery then splits that row into the 2 correct photos. All baselines unchanged EXCEPT `Scan_20260918 (6)` @20, which is the fix itself (4 correct photos; @16 byte-identical).
- Group-2 partial fix (Oct 2 2026): seam sides can now drop a small non-photo wedge instead of rejecting the whole cut when the opposite side is a clean single-photo quad. `_seam_split` calls `_clean_quad_side` (fill ≥0.92, 4–8 external corners, AR <2.2) on the large side and `_wedge_side` (area 12–25% of parent, fill <0.80, and not photo-like: `nc < 4` or `nc > 10` or AR ≥2.0) on the small side; then it keeps only the clean side. This fixes `Scan_20260925 (15)` top-right over-tall bleed; the 0.12 lower area bound is critical — without it `Scan_20260918 (6)` baseline tol-16 top-left loses an 8.8% attached fragment. The 0.80/0.25 upper bounds keep passports/strip frames.
- Group-2 border-line validator (Oct 2 2026): `_border_trim(img)` runs on the FINAL extracted piece (after `_extract`/`_mostly_blank`, before `_auto_upright`) — the only place the bleed is visible, since mask-side geometry can't separate bleed from edge fuzz (see Group-2 note below). Signature of a neighbor-photo bleed: `[foreign content strip][photo's own flat white border band][photo content]` — a real photo never has content beyond its outer border. `_bt_side` scans each side (array rotated so rows run inward) for p in 2–35% of the dimension where: the band starts at p and is full-width (row white-fraction ≥0.85), near-pure (mean ≥226, std ≤9), 12px–8% thick; the strip before p is non-white content (white-fraction ≤0.15, mean ≤215); content resumes within 25% after the band; and the entry line is a real edge (mean column-gradient ≥12, coverage ≥0.85). Up to 2 trim passes over the 4 sides; returns the image untouched if any gate fails. Fixes `Scan_20260925 (4)` @20 (guests piece shed a 583px couple-photo strip; mask boxes unchanged, only the final crop moved). It CANNOT fire where the cut has no border landmark: `Scan_20260918 (19)` (boundary sits inside the guests photo's content — no white band anywhere near the strip), `Scan_20260918 (16)` (1% sliver, below the 2% window; plus trapezoid wedges), `Scan_20260918 (14)` (extra white background at the edge — the strip IS white, opposite of the bleed signature). Those need color/texture segmentation (a true semantic validator). All 13 baselines × tol 16/20 byte-identical; only the 3 copies of `Scan_20260925 (4)`@20 differ (the accepted fix), verified with the new `--regression` mode.
- `_extract` now has a second Group-5-style fallback for fitted quads whose left/right side lengths differ (`_quad_side_diff(q)[0] > 0.13`) while the piece mask's tight bbox fill is low (`<0.80`) and angle is ≤`_MAX_DESKEW_DEG`. It returns `_axis_crop(...)` instead of q-masking the trapezoid. This removes angled white gutter triangles on low-fill white-background prints (`Scan_20260925 (21)_04`, `Scan_20260925 (4)_04`). Keep the thresholds strict: a final-image white-wedge detector + axis retry was tried Oct 2 and fixed more thin error slivers, but also changed baseline outputs (`Scan_20260918 (6)`, `Scan_20260925 (13)`, `Scan_20260925 (14)`), so it was not adopted.
- GUI worker thread must NEVER read tkinter Variables (`var.get()` cross-thread silently returns wrong values — this caused real bugs). All option values are snapshotted in the main thread by `snap()` in `poll()` into the plain `flags` dict; worker reads only `flags`, `pause_flag`/`abort` (threading.Event), and the `review` dict with queue + `threading.Event` handshake (`q.put(("review", ...))` → main thread opens `mask_editor` → sets `review["result"]` + event).
- Defaults differ on purpose: CLI `--tolerance` default is 16, GUI spinbox default is 20. Keep both in sync conceptually when changing behavior.
- `mask_editor()` returns `("ok"|"skip"|"cancel", mask)`; "ok" with an empty mask is blocked. GUI messages flow through the same `q` queue as progress (item types: `file`, `status`, `review`, `done`).

## Environment quirks

- GUI needs tkinter, which pip cannot install (Debian/Ubuntu: `sudo apt install python3-tk`). Pillow alone is not enough.
- Debian's `python3-pil` ships without `ImageTk`: `mask_editor.show()` has a base64-PNG `tk.PhotoImage` fallback (needs Tk 8.6+). Do not remove it — it is what makes the dialog work here. PPM via base64 does NOT work ("couldn't recognize image data"); PNG does.
- No xvfb on this machine; GUI automation must run against the real display (`:0`). Gotchas learned the hard way: `wait_visibility()` can hang and `wait_window()` can raise if the window/app dies — `mask_editor` uses a grab-retry loop and a try/except around `wait_window`; keep that pattern.
- Synthetic `event_generate` only reaches widgets of *mapped* windows: transient Toplevels of a withdrawn root never map. For GUI tests make the root visible and wait for `winfo_viewable()` before generating events.
